# Arquitectura implementada — S7

La aplicación evaluable está en web/. Se ejecuta con PHP 8.2 o superior, Laravel 12 y MySQL/MariaDB. VS Code es el editor; no se necesita Kiro, Node, Vite ni una clave de Gemini para esta entrega. Los archivos .kiro se conservan como documentación previa del equipo.

## Recorrido de una petición

Ruta → autenticación y sesión vigente → controlador con autorización por rol y pertenencia → modelos Eloquent de las tablas existentes → Reportes y CalculoResultados → vista Blade.

| Historia | Ruta | Controlador | Modelos principales | Vista |
|---|---|---|---|---|
| H-04 | /estudiante/reporte/{simulacro?} | EstudianteController | Usuario, Simulacro, Pregunta, Respuesta, Tema | estudiante |
| H-07 | /docente/grupos/{grupo}/simulacros/{simulacro?} | DocenteController | Usuario, Grupo, Simulacro, Respuesta | grupal |
| H-09 | /direccion/resumen/{simulacro?} | DireccionController | Grupo, Simulacro, Pregunta, Respuesta | institucional |
| H-01/H-03 | /ingresar, /salir, /inicio | AccesoController | Usuario | acceso |

Los modelos declaran nombres de tabla, claves y ausencia de timestamps. Respuesta tiene clave compuesta en SQL y se trata únicamente como modelo de lectura. No se llama a save, update, delete, migrate ni seed desde las rutas. Los archivos de migraciones del esqueleto previo permanecen como antecedente, pero no se ejecutan.

## Reglas de cálculo

- Individual: correctas / todas las preguntas × 100, un decimal. Una omisión aporta cero aciertos. Temas con menos aciertos aparecen primero.
- Grupal: errores / respuestas válidas recibidas × 100, un decimal; omisiones por separado. Solo estudiantes activos con matrícula vigente del grupo y al menos una respuesta válida.
- Dirección: el mismo cociente agregado, dos decimales; solo grupos activos de 5.º secundaria. Personas deduplicadas en el total; sin identificadores individuales en la vista. Los grupos sin respuestas se excluyen y se cuentan.
- No hay división entre cero: porcentaje de error nulo cuando no hay respuestas. Se excluyen preguntas y respuestas inconsistentes y se informa el conteo.
- Se elige la fecha de aplicación más reciente, con identificador como desempate. Un simulacro asignado sin respuestas puede ser el más reciente: su pantalla explica el estado y ofrece las demás selecciones.

## Acceso y privacidad

Autenticación con hash bcrypt existente, sin rehash que escriba en SQL; CSRF y renovación de sesión al ingresar. Caducidad absoluta de ocho horas, sesión cifrada en archivos, límite de cinco intentos por minuto e IP. Autorización por rol y grupo antes del cálculo. Eloquent parametriza entradas, Blade escapa texto, las respuestas llevan no-store y cabeceras de protección. Los errores de SQL se presentan como 503 sin consulta ni credenciales. Los registros técnicos evitan contraseñas y respuestas de alumnos. No se implementa escritura en registro_acceso porque la cuenta SQL es de solo lectura; auditoría persistente queda como deuda explícita.

La demostración B0 es una preparación independiente, anterior a las consultas: tools/preparar_demo.php crea una base nueva, carga datos ficticios y genera una cuenta SELECT. Se niega a sobrescribir una base o .env existente. No actúa sobre la base de los compañeros. Véase ADR-004 y la guía de ejecución.

## Límites

H-02 administración completa, H-05 comparación, H-06 orientación, H-08 detalle y H-10 Gemini/MCP no se declaran terminadas. Las historias comunes H-01/H-03/H-11 se implementan en la medida necesaria para estos tres cortes. Con datos institucionales reales deben revisarse codificación del nivel, roles, volúmenes, políticas de registro, TLS y mantenimiento de dependencias. Esta entrega es local, con datos ficticios.
